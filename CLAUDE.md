# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Word Bank: a local single-user FastAPI app (vanilla JS front end, no build step) that shows advanced English vocabulary entries daily, enriches them with an LLM and real Guardian quotes, and collects accepted entries into a PDF. The app is called **Word Bank** (it was formerly "Word Hoard"; "hoard" still appears in the vocabulary list as an entry, which is correct).

README.md is the user's primer: setup, daily use, troubleshooting, problems fixed and remaining limitations. Its troubleshooting table quotes the exact messages raised in `journal.py` and `server.py`, so update it whenever a user-facing message changes. DEBUG.md is the latest debugging and test report.

## Commands

- Run the app: `uv run server.py` (serves http://127.0.0.1:8000 and opens a browser)
- Validate the vocabulary part files: `uv run build_vocab.py`
- Rebuild `VOCABBASE.TXT` from `parts/`: `uv run build_vocab.py --write`
- Rebuild `dictionary.json` from Wiktionary: `uv run build_dictionary.py` (downloads the 523 MB kaikki.org extract to the gitignored `downloads/` if missing; about 2 minutes). Rerun after changing the master list
- Run the tests: `uv run pytest`; one test: `uv run pytest tests/test_journal.py::test_accept_removes_from_list_and_builds_pdf`

Tests use temporary data files, a fixed "today", and fakes only at the two network boundaries, `llm.completion` and `guardian.search` (`tests/conftest.py`), so the real card, detail, quote-choosing and revision code runs without touching `data/` or spending API quota. Guardian's retry tests use `conftest.REAL_SEARCH`. `conftest` also makes the dictionary empty; tests that need Wiktionary data patch `llm.dictionary.entries`. The two PDF-lock tests are Windows-only. No linter is configured. The app requires a `.env` with `GROQ_API_KEY`, `OPENAI_API_KEY`, `GUARDIAN_API_KEY` and `LLM_MODEL` (a LiteLLM model string, e.g. `groq/openai/gpt-oss-120b`); `LLM_FALLBACK_MODEL` is optional (default `openai/gpt-4o-mini`). Tests fix both model names in `conftest.py` (`PRIMARY`, `FALLBACK`).

## Architecture

Layering: `server.py` (thin routes) -> `journal.py` (all business rules) -> `db.py`, `vocab.py`, `llm.py` (-> `dictionary.py`), `guardian.py`, `pdf.py`. Routes should stay thin; rules belong in `journal.py`. `config.py` loads `.env` once, treating a blank value as unset (litellm's `validate_environment` counts a blank key as present); `server.py` refuses to start if `config.missing_settings()` names anything.

- **Errors shown to the user**: `journal.py` raises `journal.Refused(message)`, which `server.py` turns into HTTP 400 `{"error": message}`. Guardian (`urllib.error`) and LLM (`openai.APIError`, the base of all litellm errors; `litellm.APIError` is not, and `openai` is declared in `pyproject.toml` for this) failures are mapped to 502 with a readable message. `static/app.js` `api()` shows `error` as a toast.
- **Front end**: the drawer is a modal dialog; `setModal` in `static/app.js` makes it `inert` while closed and the page behind it `inert` while open, which also keeps Tab inside it. `drawerAction` locks the whole drawer footer (feedback, Edit, Accept, Delete) while any of them runs; `setFooter` treats an entry as loaded when it has a `detail`.
- **Local only**: a middleware refuses requests whose `Host` or `Origin` is not `127.0.0.1:8000`/`localhost:8000`.
- **Entry lifecycle**:
  1. *Card*: on add (daily random pick, "more", or typed), `llm.card_summaries` produces pronunciation, respelling and principal meaning (see **Wiktionary** below). The daily pick happens lazily on the first `GET /api/today` of a day and is recorded in the `days` table. `journal.PAGE_LOCK` serialises every addition to a day's page (daily pick, "5 More", typed), so overlapping requests cannot make the pick twice, and entries already on the page are excluded by fold. Blank typed entries are refused, and "5 More" with nothing left to pick is refused without an LLM call.
  2. *Detail*: generated lazily on first open (`journal.detail`, under a per-entry lock in `DETAIL_LOCKS`, so concurrent opens pay once): LLM senses (based on Wiktionary's, when there are any)/examples/synonyms plus up to 3 Guardian quotes, quotes first, capped at `MAX_EXAMPLES`.
  3. *Revise*: LLM applies free-text feedback. Guardian quotes are passed by number and can only be kept or dropped, never reworded. A drop counts only if the reply also sets `feedback_asks_to_remove_quotes` (`llm.Revision`): both Groq and gpt-4o-mini dropped quotes unasked, about 1 in 4 revisions with a keep-list and 1 in 8 with an ungated drop-list, and 0 of 33 with the gate. The pronunciation and respelling are gated the same way (`feedback_asks_to_change_pronunciation`), since models rewrote them on unrelated feedback and would otherwise overwrite Wiktionary's IPA. The LLM call runs outside `COLLECTION_LOCK`; the entry is checked again under it before writing, so an accept or delete made meanwhile wins.
  4. *Accept*: final; rebuilds the PDF, then marks the row accepted and removes the entry from `data/remaining.txt`.
  5. *Delete*: allowed for today's entries or any accepted entry; for an accepted one the PDF is rebuilt first, then the row is deleted and the master-list spelling restored to `remaining.txt` (a typed entry that is not in the master list is simply gone, and can be typed again).
  The PDF goes first so a failure (typically the file locked by a PDF viewer) leaves nothing changed. `journal.COLLECTION_LOCK` serialises accept, delete and the write of a revision, which otherwise race on the collection and on `output/vocabulary.tmp`. Entries are compared with `vocab.fold` (case, accents, œ/æ), so the same entry cannot be accepted twice.
  Past days are read-only and show only accepted entries.
- **Storage** (`db.py`): SQLite `data/vocab.db`. An entry row stores card fields as JSON in `card` and the detail as JSON in `detail`; `to_dict` flattens card fields into the top-level dict. `db.connect()` is a context manager: one transaction, committed (or rolled back) and then closed. It runs the `CREATE TABLE IF NOT EXISTS` schema on every connection (about 0.1 ms), so a deleted database file is recreated; do not cache it. Read results inside the `with` block. Examples are `{text, source, title, url, date}`; `source: None` marks an LLM-written example.
- **Vocabulary list**: `VOCABBASE.TXT` is the never-modified master list: first 3,500 lines are words, the rest phrases (`vocab.is_phrase` relies on this ordering). The master list is read once and cached (`vocab.master_list`, `vocab.master_positions`). `data/remaining.txt` is the working copy of not-yet-accepted entries, created from the master on first run; blank lines in it are ignored. Unlike the master, it is re-read on every add, accept and delete.
- **LLM** (`llm.py`): every call goes through `ask(prompt, schema)` using LiteLLM structured output with a Pydantic `response_format`. `ask` tries `config.LLM_MODEL` (Groq) once with a 30 s timeout; on any failure except a setup mistake it logs a warning and asks `config.LLM_FALLBACK_MODEL` (default `openai/gpt-4o-mini`, 60 s) at once. Groq is never waited for: its per-minute limit (8,000 tokens), daily allowance (200,000 tokens), outages, timeouts and malformed replies all switch immediately; a refusal costs about 0.5 s. Every call passes `max_retries=0`, so the OpenAI SDK's own retries cannot add hidden waits. Public functions use the `retrying` decorator (tenacity): `MAX_ATTEMPTS` (3) with 1 s and 2 s waits, each attempt trying Groq first again. Raising `ValueError` on a bad reply (wrong count, out-of-range numbers) triggers a retry. `permanent()` errors, HTTP 401, 403 or 404 and non-`Exception` errors such as `KeyboardInterrupt`, are neither retried nor sent to the fallback, so a wrong key or model name is reported, not hidden. Judge LLM errors by `status_code`, not class: litellm reports Groq's "Invalid API Key" as a `BadRequestError` with status 401. `server.llm_failed` names the failing provider from `exc.llm_provider`. `litellm.suppress_debug_info` hides litellm's per-failure banner. Guardian retries only network errors, 429 and 5xx; it has no fallback. Pronunciation is blanked for entries of more than two words (`make_card`).
- **Wiktionary** (`dictionary.py`, `build_dictionary.py`): `dictionary.json` (committed, about 1.5 MB, CC BY-SA, credited on the PDF title page) maps `vocab.fold(entry)` to sense groups `[{ipa, senses}]`, one group per British IPA (`""` for senses with none), so homographs like "buffet" keep each pronunciation with its own senses. It covers 4,426 of 5,000 entries; 2,384 have a British IPA. Only IPA tagged Received-Pronunciation, UK or British is taken (untagged is often American), whole transcriptions only, normalised to the app's notation (`ɹ` to `r`, no syllable dots or tie bars). Senses drop obsolete ones and form-of/alt-of links; at most `MAX_SENSES` (8) per entry. An entry with no senses of its own that is an alternative spelling follows every single-target main spelling, sharing the limit equally ("gibe" -> jibe, gybe); multi-target links are wiktextract's comma splits ("close but no cigar" -> "close") and are not followed. The card prompt lists each entry's numbered groups; `llm.Summary` returns the chosen `group` and the code copies that group's IPA, so the model never retypes it, falling back to the model's own IPA for group 0 or a group with no IPA. `Summary` also echoes `entry`, and `llm.fits` rejects (and so falls back or retries) a batch whose entries do not match in order (compared by `letters`: fold, then alphanumerics) or names a group that does not exist: gpt-4o-mini returned one card per group instead of one per entry. `entries()` is cached; typed entries not in the master list get no Wiktionary data.
- **Guardian** (`guardian.py`): builds a quoted-phrase AND query (placeholders like "one's", "someone" are split out), then splits article text into sentences (`SENTENCE_END`: at . ! ? before a capital, digit or quote, and at the "•" bullets the Guardian uses before author notes and letter footers) and regex-matches the entry in them (the first word matches only its regular inflections via `stems` and `INFLECTIONS`, so "abate" matches "abating" but not "abattoir"; placeholders are wildcards) to produce candidates for `llm.choose_quotes`.
- **PDF** (`pdf.py`): ReportLab with bundled DejaVu fonts (needed for IPA), built to `output/vocabulary.tmp` and then swapped into `output/vocabulary.pdf`. Bookmark keys are generated (`heading-N`, renumbered each build pass in `JournalDoc.beforeDocument`) because ReportLab's contents page breaks on a quote or apostrophe in a key. Text put into ReportLab markup must be escaped, and attribute values need `"` escaped too. `/api/pdf` also answers HEAD, so the page checks for the PDF without downloading it.

## Testing against the real services

The unit tests never call Groq or The Guardian. To check behaviour end to end with real calls, without touching the user's progress:

1. Copy the code, `VOCABBASE.TXT`, `fonts/`, `static/`, `data/` and `output/` to a scratch folder.
2. Put a small start script in that folder (it imports `server` and runs `uvicorn.run(server.app, host="127.0.0.1", port=8000)`). Because the script lives in the copy, its imports and every data path resolve to the copy.
3. Run it from the project folder: `uv run --env-file .env python <scratch>/start_script.py`. uv splits the `--env-file` value on spaces, and this project's path contains one, so pass the relative `.env` rather than an absolute path. Never copy `.env` itself.
4. To force a fresh daily pick in the copy, delete today's row from its `days` table.

To override a setting for one run, set it in front: `GROQ_API_KEY=bad uv run --env-file .env python <scratch>/start_script.py` (a variable already set in the environment wins over `--env-file`).

Groq's free tier allows 8,000 tokens per minute and 200,000 per day for `gpt-oss-120b`. A full end-to-end run can use the daily allowance; after that every call falls back, which is expected and should give no 502s. Each fallback logs one line containing `using openai/gpt-4o-mini` with Groq's reason, so counting those lines counts fallbacks. To force failures: `GROQ_API_BASE=http://127.0.0.1:9/openai/v1` (unreachable, falls back), a local socket that never answers on another port (times out after 30 s, falls back), `GROQ_API_KEY=bad` (reported, no fallback).

## Cautions

- `data/vocab.db`, `data/remaining.txt` and `output/vocabulary.pdf` are tracked in git and hold the user's real progress. Do not delete or reset them when testing; use a copy.
- Each LLM or Guardian call costs API quota; detail generation makes several. Wiktionary senses roughly doubled the card prompt (median 349 to 748 tokens per batch).
- Accept and accepted-entry delete rebuild the whole PDF: about 13 s at 1,500 entries, 55 s at 5,000.
